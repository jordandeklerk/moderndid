# moderndid tests

These rules cover where a test goes, how it is laid out, and how it checks numbers, errors, and warnings. `docs/source/contributing/testing.rst` gives the reasoning. The later half of `tests/didtriple/test_ddd.py`, from `test_ddd_alpha_above_tenth_uses_005_on_every_route` on, shows most of it in one file, and `tests/etwfe/` and `tests/didinter/` are the cleanest folders.

- `moderndid/<family>/<module>.py` is tested in `tests/<family>/test_<module>.py`, flat even when the module sits in a subfolder, so `didtriple/estimators/ddd_mp.py` is tested in `tests/didtriple/test_ddd_mp.py`. Plots are tested in `tests/plotting/` and the GPU backend in `tests/core/test_gpu*.py`. Every test folder has an `__init__.py` and a `conftest.py`.
- A test module opens with `"""Tests for <subject>."""` and its imports. Import the API under test from `moderndid`, and import a submodule only to reach a private helper. An optional dependency such as pyfixest or formulaic loads at the top through `from tests.helpers import importorskip`, which raises instead of skipping when `MODERNDID_REQUIRE_ALL_DEPS` is set. A slow module sets `pytestmark = pytest.mark.slow` after its imports, so `pixi run -e dev tests-core` leaves it out.
- Tests are flat functions with no docstrings and no comments, named as behavior sentences such as `test_ddd_mp_never_treated_units_lost_to_balancing_leave_no_comparison`. There are no test classes and no module-level constants.
- Fixtures live in the folder's `conftest.py`, each with a one-line docstring that has no comma, and never in a test file. Reuse one before adding another, such as `mpdta_data` in `tests/did/conftest.py`. Parametrize over fixtures by name with `request.getfixturevalue(data_fixture)`, and pass arguments shared by several calls as a `spec` dict with `**spec`.
- Lay a test out as its inputs, a blank line, the calls, a blank line, and the asserts.
- Compute the expected value independently of the code under test. Rebuild standard errors from the stored influence function, as `test_ddd_mp_cluster_without_boot_sums_within_clusters` does with `np.bincount`, run a lower-level estimator on a hand-built cell, use a closed form, or check an invariance such as integer weights matching replicated units, a parallel run matching a sequential one, or shuffled rows matching the original order. Never paste moderndid's own output in as the expected value, and never stop at shape or type checks.
- When a test compares two runs, also assert that the change it tests moves the estimate, as in `assert np.max(np.abs(weighted.att - unweighted.att)) > 1e-3`, so the test can't pass vacuously.
- Compare with `np.testing.assert_allclose(result, expected, rtol=..., atol=...)` and explicit tolerances. Deterministic paths agree to `rtol=1e-12` or `1e-10`. Use `np.testing.assert_array_equal` for labels and for runs that must be identical. Tighten a tolerance to what the code achieves, and never widen one to make a test pass.
- Build data with the `gen_*` simulators in `moderndid/core/data.py` at `random_state=42`, or with `load_mpdta()`. Draw anything else from `np.random.default_rng(<seed>)`, never `np.random.seed`, `np.random.normal`, or `RandomState`. Pass `random_state` to every call that draws a bootstrap, which includes `att_gt` under its default `cband=True`, since `aggte` then draws one for the simultaneous bands.
- Test every error with `pytest.raises(ValueError, match=...)` on a distinctive part of the message, wrapped in `re.escape` when it holds regex characters. Never write `pytest.raises(Exception)`, which also passes on an `AttributeError` from a missing export.
- Test an expected warning with `pytest.warns(UserWarning, match=...)`. To show that no warning is raised, record with `warnings.catch_warnings(record=True)` and `warnings.simplefilter("always")`, then assert on the messages. A `filterwarnings` mark names only the warning the test is about. Since suppression hides real problems, the `forbid_errstate` fixture in `tests/conftest.py` makes `np.errstate` raise, so a test can prove a guarded path needs none.
- For bootstrap results that must match exactly, hand the code fixed draws through the `fixed_draws` and `draws_from_weights` fixtures in `tests/conftest.py`.
- `tests/conftest.py` skips every test marked `gpu` unless CuPy reaches a CUDA GPU. A test with an independent reference takes the `xp` fixture, runs under NumPy and CuPy, and asserts that promised device arrays come back as `xp.ndarray`. A comparison of a GPU run with the CPU run of the same call carries the marker alone and takes CuPy from the `cp` fixture. Test modules never import CuPy and switch backends only through `use_backend` or a `backend` argument. Assertions on GPU results allow for rounding in the last bits and judge CuPy's random draws by their distribution alone.
- Don't copy the test classes in `tests/core/` and `tests/didtriple/test_nuisance.py`, the fixtures inside `tests/didhonest/` test files, the `np.random.seed` calls in older files, or the smoke-only tests at the top of `tests/didtriple/test_ddd.py`.
